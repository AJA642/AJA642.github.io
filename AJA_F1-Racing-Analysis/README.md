# Formula 1 World Championship — SQL Analysis

A SQL + Python case study on 75 years of Formula 1 results: which
constructors dominated which eras, whether grid position still decides
races, driver consistency versus boom-or-bust seasons, home-circuit
effects, pit stop trends, reliability over time, and the closest
championship near-misses in the sport's history. Built as a portfolio
piece for Data Analyst / BI roles — the main deliverable is
[REPORT.md](REPORT.md), a short written case study with charts.

## Dataset

[Kaggle: `rohanrao/formula-1-world-championship-1950-2020`](https://www.kaggle.com/datasets/rohanrao/formula-1-world-championship-1950-2020)
— the Ergast F1 database, a genuinely relational dataset covering every
World Championship season from 1950 to the present. Twelve CSVs are used
here:

- `races.csv`, `seasons.csv`, `circuits.csv` — the calendar
- `drivers.csv`, `constructors.csv`, `status.csv` — reference/lookup tables
- `results.csv` — one row per driver per race (1,125 races, 26,759 results)
- `driver_standings.csv`, `constructor_standings.csv` — points/position
  after every round
- `qualifying.csv` — qualifying session results
- `pit_stops.csv`, `lap_times.csv` — session-level timing data

Not included in this repo (see `.gitignore`) — download from Kaggle and
place all twelve CSVs in `data/` before running anything. The dataset's
name says "1950-2020" but the version used here (downloaded 2026) has
been extended by its maintainer through the 2024 season.

### A real coverage gap, not a bug

`pit_stops.csv` only starts in **2011** and `lap_times.csv` only in
**1996** — Formula 1 didn't record this data electronically before then,
so it isn't a loading error or a filtered-out range. Any query using
those two tables is scoped to the years the data actually covers; see
`queries.sql` and the Limitations section of `REPORT.md` for exactly
where this matters.

## How to run

Requires the twelve CSVs in `data/` (see above). A virtual environment
with the dependencies is already set up in `venv/`.

```bash
# from this folder
source venv/bin/activate
python load_data.py     # builds f1.db from the CSVs (a few seconds)
python analysis.py      # runs queries.sql, prints key figures, writes charts/
```

`load_data.py` is idempotent — it rebuilds `f1.db` from scratch each run.
`analysis.py` overwrites the PNGs in `charts/` each run too.

If setting up fresh instead of using the included `venv/`:
```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

## Tech stack

Python 3, pandas, SQLite (via `sqlite3`), matplotlib. No frameworks, no
notebook — plain scripts, so the whole pipeline runs end-to-end from the
command line.

## Notes on the SQL

`queries.sql` uses CTEs and window functions where they're the right
tool, not just for show:

- **Constructor dominance by decade** (`constructor_dominance_by_decade`)
  uses `RANK()` partitioned by decade to pull each era's top 3
  constructors in a single pass.
- **Grid-vs-finish correlation** (`grid_vs_finish_correlation`) computes
  Pearson's *r* from its raw definition (sums of x, y, xy, x², y²) —
  SQLite has no built-in `CORR()` — split by the pre/post-2010 aero-rules
  era.
- **Driver consistency** (`driver_consistency_by_season`) computes
  variance via the `E[x²] − E[x]²` identity (no built-in `STDEV()`
  either), square-rooted back to a standard deviation of finishing
  position per driver-season.
- **Home-circuit advantage** (`home_advantage_overall` /
  `_by_nationality`) is a self-join: for every home-race result, it
  compares that result to the *same driver's* average finish across
  their *other* races that *same season*, computed per-race so a
  driver's home result never leaks into its own baseline. Nationality →
  country is an explicit, necessarily-incomplete mapping (see the query
  comments) — dual nationalities and countries with no F1 circuit in
  this dataset are excluded rather than guessed at.
- **Pit stop trend** (`pit_stop_trend_same_circuit`) controls for the
  fact that different circuits have different pit lane lengths/speed
  limits by also tracking one circuit (Monza) that ran every season
  2011-2024, rather than trusting the raw cross-circuit average alone.
- Every ranking-style query has a minimum-sample floor (`HAVING COUNT(*)
  >= ...`) so a handful of races/starts can't outrank a real multi-season
  pattern — e.g. driver-seasons need ≥10 starts and ≥5 classified
  finishes before they're eligible for the consistency ranking, and
  circuits need ≥200 starts before they're eligible for the DNF-rate
  ranking.
